# 테스트

## 전략

**테스팅 트로피 하나로 간다.** 층은 아래에서부터 정적 분석과 단위, 통합, e2e다. 비율 목표를 세우지 않는다. 판정 대상은 개수가 아니라 "이 테스트가 빨간불을 냈을 때 무엇이 깨졌는지 이름으로 말할 수 있는가"다.

**정적 분석 층은 이미 넷이 서 있다.** `pnpm type:check`와 `pnpm lint`, `pnpm lint:arch`(Steiger), `scripts/validate-seo.mjs`의 frontmatter 게이트다. 이 넷이 막는 것을 테스트로 다시 확인하지 않는다.

**기본 동작은 삭제다.** 테스트를 새로 만들기 전에 같은 것을 보는 기존 테스트가 있는지 먼저 읽는다. 스위트가 커지면 늘리는 대신 줄인다. 남기는 테스트에는 "이게 깨지면 무엇이 조용히 잘못되는가"를 한 문장으로 댈 수 있어야 한다.

## 값이 나는 자리

공통 성질은 하나다. 틀려도 화면이 그려지고 빌드가 통과한다.

| 자리                       | 어디                                              | 틀리면                                     |
| -------------------------- | ------------------------------------------------- | ------------------------------------------ |
| 콘텐츠 파싱과 파생값       | `entities/*/lib`, `shared/lib`                    | 틀린 글 페이지가 조용히 배포된다           |
| 공개 여부와 노출 정책      | `privatePolicy.integration.test.ts`, sitemap, RSS | 비공개 글이 새어 나가고 화면은 정상이다    |
| 기계만 읽는 산출물         | `shared/seo`, `app/api-routes`                    | 며칠 뒤 유입이 줄어드는 모습으로 돌아온다  |
| 브라우저에서만 드러나는 것 | e2e                                               | 포커스와 인쇄, 모션 축소는 jsdom이 못 본다 |

## 값이 적은 자리

화면 배치만 하는 컴포넌트의 렌더 확인, 상수를 그대로 다시 적는 단언, 배럴과 재노출의 형태 확인, 라이브러리가 하는 일의 재확인이다. 재노출은 예외가 하나 있다. metadata 사슬이 끊기면 조용히 틀린 채로 배포되므로 `src/app/__tests__/metadata-reexport.test.ts`는 남긴다. 근거는 `seo.md`에 있다.

## 층마다 소유하는 것

같은 보장을 두 층이 함께 보면 하나를 지운다. 어느 쪽을 지울지는 아래로 정한다.

**단위와 컴포넌트가 소유한다.** 우리가 직접 짠 로직이다. 이벤트 짝짓기, 상태 전이, 분기 있는 순수 함수, 파생값 계산. `Dialog.test.tsx`가 pointerdown과 click을 짝지어 배경 클릭을 가려내는 것과 겹친 대화상자의 잠금 수를 세는 것이 이 자리다.

**e2e가 소유한다.** jsdom이 흉내내지 못하는 것만이다. 실제 Tab 순회 순서, 실제 포커스 복귀, 스크롤바로 인한 가로 밀림, 배경 요소의 포커스 차단, `@media print`, 모션 축소, 클립보드, 자바스크립트를 끈 응답 HTML.

**둘 다 아니면 둘 다 지운다.** native `<dialog>`의 ESC 닫기와 `aria-modal` 부여는 브라우저 동작이라 어느 층도 확인하지 않는다.

## 지우는 기준

하나라도 걸리면 삭제 후보다.

1. 구현 상세를 단언한다. 내부 상태, 클래스명, `container.querySelector`, 호출 횟수
2. role이나 텍스트로 잡을 수 있는데 test id로 잡는다
3. 하위 층이 이미 같은 보장을 낸다. 지울 때 그 파일과 케이스 이름을 근거로 댄다
4. 같은 부류를 여러 개 두고 있다. 부류마다 하나면 충분하다
5. 정적 분석 넷 중 하나가 이미 막는다
6. 상수나 설정값을 그대로 다시 적는다
7. 라이브러리나 프레임워크가 하는 일을 확인한다
8. MSW로 요청 발생이나 요청 형태를 단언한다
9. 스냅샷이다
10. async 서버 컴포넌트를 렌더해 단언한다. Next 문서가 e2e로 하라고 명시한다
11. `act`로 직접 감쌌거나 `user-event`로 될 것을 `fireEvent`로 한다
12. 단언 없이 조회만 하거나 항상 참인 단언이다
13. e2e인데 브라우저가 필요 없다

## 지우면 안 되는 것

지우는 기준에 걸려도 아래에 함께 걸리면 지우지 않고 고친다.

1. 틀려도 화면이 그려지고 빌드가 통과하는 자리
2. 실제로 깨진 적이 있고 사고 기록이 있다. 케이스 이름에 그 사고를 적어 둔다
3. 브라우저에서만 드러난다
4. 자동 규칙 검사가 못 잡는 접근성이다. 포커스 순서와 키보드 조작, 포커스 갇힘, 랜드마크
5. 콘텐츠가 정책대로 걸러지는가를 본다
6. 분기가 있는 순수 함수의 경계값이다
7. 실패를 값으로 돌려주는 계약을 지키는가를 본다. `no-fallback.md`가 정한 축소 동작
8. 부류에서 마지막 하나다
9. `/** @vitest-environment node */` 같은 지시문이 붙어 있다. 케이스를 지우다 파일 머리를 함께 지우지 않는다
10. 다른 테스트가 쓰는 공유 자산이다. `src/shared/test/`와 `e2e/helpers.ts`, `e2e/dialog-a11y.ts`

## 지울 때 확인하는 것

1. 지우려는 케이스가 검사하는 대상 코드를 실제로 연다. 이름만 보고 판정하지 않는다
2. "지우고 그 코드를 망가뜨리면 무엇이 잡는가"를 답한다. 아무것도 못 잡으면 그 테스트는 값이 있다
3. 하위 층 중복이 근거면 그 파일과 케이스 이름을 확인한다. 같은 작업에서 그쪽을 지우고 있지 않은지 마지막에 다시 본다
4. 지운 뒤 게이트를 전부 돌린다
5. 커버리지를 전후로 대조한다. 목표 수치로 삼지 말고 급락한 자리가 있는지만 본다. 많이 지웠는데 커버리지가 거의 그대로면 지운 것이 중복이었다는 뜻이다

## 하지 않기로 한 것

Vitest Browser Mode 도입, 시각 회귀 테스트, 뮤테이션 테스트 도구(Stryker) 도입, 커버리지 수치 목표. 넷 다 이 저장소 규모에서 유지 비용이 얻는 것보다 크다.

## 알려진 공백

`post-views.test.ts`가 redis 모듈을 통째로 대체하고 `hasRedisCredentials`를 `true`로 고정한다. 그래서 자격 증명이 없는 갈래와 catch 갈래를 어느 케이스도 지나지 않는다. 둘 다 조회수를 0으로 돌려주는 자리라, `no-fallback.md`가 허용한 축소 동작이 실제로 그렇게 도는지 확인되지 않는다.
