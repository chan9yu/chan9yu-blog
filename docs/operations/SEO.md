# 검색 유입 운영

코드로 할 수 없는 SEO 작업을 적는다. 코드가 이미 하는 일은 product/SPEC.md가 맡는다.

남은 격차는 도메인 권위와 외부 링크, 콘텐츠 깊이라 코드로 만들 수 없다. 이 문서가 그 부분을 다룬다.

## 코드가 이미 하는 것

아래는 빌드가 강제하므로 발행할 때 따로 점검하지 않는다.

- 제목 60자 이내, 설명 120자에서 160자
- slug는 영문 소문자와 숫자, 하이픈만. 디렉토리명과 일치
- 어기면 빌드가 실패한다

메타데이터와 JSON-LD 4종, OG 이미지, sitemap, RSS, robots도 코드가 만든다. 그중 발행 판단에 영향을 주는 것은 하나다. 글이 한 편뿐인 태그는 사이트맵에서 빠진다. 그 태그 페이지는 계속 열리고 noindex로 나가되 링크는 따라가게 둔다. 같은 태그로 두 번째 글을 쓰면 다음 배포에서 사이트맵에 들어온다.

## 검색 엔진 등록

한 번만 하면 된다.

| 서비스                | 주소                             | 비고                                  |
| --------------------- | -------------------------------- | ------------------------------------- |
| Google Search Console | search.google.com/search-console | 도메인 속성으로 등록하고 DNS로 확인   |
| Bing Webmaster Tools  | bing.com/webmasters              | Search Console에서 가져올 수 있다     |
| 네이버 서치어드바이저 | searchadvisor.naver.com          | 한국 유입에 필요하다. RSS도 따로 등록 |
| 다음 검색등록         | 선택                             | 점유율은 낮지만 비용이 없다           |

전부 sitemap 주소(`/sitemap.xml`)를 제출한다. 네이버는 RSS(`/rss`)를 따로 받으므로 함께 넣는다.

등록 후 이틀쯤 지나 색인된 페이지 수가 0보다 큰지 확인한다.

### 소유 확인 meta

소유 확인을 HTML 태그로 하는 서비스는 Vercel 프로젝트 환경 변수에 값을 넣어야 한다. 값이 있으면 다음 배포부터 head에 meta가 실리고, 비워 두면 그 meta 자체가 나가지 않는다.

| 환경 변수                              | 값을 어디서 받는가                                      |
| -------------------------------------- | ------------------------------------------------------- |
| `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` | Search Console의 HTML 태그 확인에 적힌 content 값       |
| `NEXT_PUBLIC_NAVER_SITE_VERIFICATION`  | 서치어드바이저의 사이트 소유확인 HTML 태그의 content 값 |

구글은 위 표대로 도메인 속성을 DNS로 확인하므로 이 변수 없이도 등록이 끝난다. 네이버는 서치어드바이저에서 발급받은 값을 넣어야 소유 확인이 통과한다.

값을 넣고 배포한 뒤 각 콘솔에서 확인 버튼을 누른다. 확인이 끝나도 변수는 지우지 않는다. meta가 사라지면 소유 확인이 풀릴 수 있다.

## 월 1회 점검

### Search Console

- 성능에서 노출과 클릭, 평균 순위의 월별 추세를 본다
- 색인 생성됨과 제외됨의 비율을 본다. 제외가 늘면 이유를 확인한다
- sitemap에 제출한 수와 색인된 수가 벌어지는지 본다
- 향상 항목에서 BlogPosting과 BreadcrumbList가 유효한지 본다

### 검색어

성능의 검색어 목록에서 평균 순위를 기준으로 나눠 대응한다.

- 30위 밖이면 그 글의 내용을 보강한다
- 11위에서 20위 사이면 순위보다 클릭률 문제다. 설명과 OG 이미지를 손본다
- 10위 안이면 그 주제로 글을 하나 더 써서 묶는다

### AI 답변 엔진

ChatGPT와 Perplexity, Claude, Google AI 개요에 대표 주제를 직접 물어보고 블로그가 출처로 인용되는지 기록한다. 인용을 결정하는 것은 콘텐츠 품질과 외부 권위이지 코드가 아니다.

AI 크롤러는 robots.txt에서 전부 허용한다(2026-08-26 결정). 검색 노출용 봇(OAI-SearchBot, Claude-SearchBot, PerplexityBot)을 막으면 위 인용 유입이 끊긴다. 학습용 봇(GPTBot, ClaudeBot, CCBot)만 막는 선택은 검색 노출과 무관한 별도 결정이고, 막으려면 `src/app/api-routes/robots.ts`의 rules를 배열로 바꿔 봇별 항목을 더한다.

### 성능

PageSpeed Insights로 모바일 지표를 잰다. 기준과 절차는 operations/RUNBOOK.md의 릴리스 전 검증에 있다.

## 외부 링크 쌓기

도메인 권위는 시간이 드는 일이라 꾸준히 한다.

**크로스 포스팅.** dev.to와 Medium, Hashnode에 옮겨 실을 때 반드시 원문을 정본으로 지정한다. 지정하지 않으면 옮긴 글이 원문보다 위에 뜬다.

**커뮤니티 공유.** 국내는 GeekNews와 OKKY, Disquiet이 있고 해외는 Hacker News와 Lobsters가 있다. 글마다 뿌리지 않는다. 스스로 읽을 만하다고 판단한 글만 올린다.

**인용될 글 쓰기.** 남이 링크를 걸 이유가 있어야 링크가 생긴다. 다른 데 없는 측정치나 끝까지 파고든 사례가 그 이유가 된다.

## 콘텐츠 쪽에서 할 것

**첫 단락에 핵심어를 넣는다.** 검색 엔진이 첫 단락에 가중치를 둔다. 억지로 넣지 말고 무엇에 대한 글인지 첫 문장에서 밝히면 자연히 들어간다.

**시리즈 안에서 서로 링크한다.** 각 편의 시작이나 끝에 다른 편 링크를 한둘 넣는다. 독자가 이어 읽고 검색 엔진이 묶음으로 인식한다.

**질문에 답하는 제목을 쓴다.** 검색어는 대개 질문 형태다. 소제목을 질문으로 두면 검색 결과 상단 요약에 뽑힐 여지가 생긴다.
