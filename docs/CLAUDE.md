# docs 안내

문서를 어디에 두고 어떤 순서로 채우는지 적는다. 한국어 작성 규칙은 루트 `CLAUDE.md`를 따른다.

## 배치 기준

성격으로 나눈다. 만드는 것은 `product/`, 보이는 것은 `design/`, 굴리는 것은 `operations/`, 생성 도구에 넣는 것은 `prompts/` 다.

| 파일                              | 답하는 질문                                    |
| --------------------------------- | ---------------------------------------------- |
| `product/PRD.md`                  | 누구의 어떤 문제를 왜 푸는가                   |
| `product/SPEC.md`                 | 각 기능이 정확히 어떻게 동작하는가             |
| `product/ROADMAP.md`              | 무엇을 어떤 순서로 만드는가                    |
| `design/DESIGN.md`                | 블로그가 어떤 인상을 주는가                    |
| `design/DESIGN-SPEC.md`           | 각 화면에 무엇이 어떻게 놓이는가               |
| `operations/RUNBOOK.md`           | 어떻게 배포하고 깨졌을 때 무엇을 하는가        |
| `operations/SEO.md`               | 코드 밖에서 검색 유입을 위해 무엇을 하는가     |
| `prompts/CLAUDE-DESIGN-PROMPT.md` | 화면 시안을 받으려고 생성 도구에 무엇을 넣는가 |
| `prompts/IMAGE-ASSET-PROMPT.md`   | 배포되는 이미지 파일을 만들려고 무엇을 넣는가  |

태스크 체크리스트는 `product/ROADMAP.md`의 절로, 기술 결정 기록은 `product/SPEC.md`의 절로, 컴포넌트 목록은 `design/DESIGN.md`의 절로 들어간다. 별도 파일로 두지 않는다.

`product/`와 `design/`은 만들 것을 정하고 `operations/`는 이미 돌아가는 것을 다룬다. 읽는 때가 다르다. 앞의 둘은 무언가를 새로 만들기 전에 읽고, `operations/`는 배포하거나 문제가 생겼을 때 읽는다.

`prompts/`를 따로 두는 이유는 수명이 다르기 때문이다. 다른 폴더의 문서는 지금 사실에 맞춰 계속 고친다. 프롬프트는 결과물을 만들어 낸 입력이라 고치지 않고 보존해야 같은 결과를 다시 받을 수 있다. 한 폴더에 섞어 두면 어느 쪽 규칙을 따라야 하는지 파일마다 헷갈린다. 파비콘이나 OG 이미지 문구처럼 생성 도구에 넣는 것이 늘어나도 이 폴더에 쌓는다.

## 채우는 순서

빈 문서를 채울 때 이 순서로 간다.

1. `PRD.md`부터 쓴다. 문제와 범위가 서기 전에는 다음으로 가지 않는다
2. `DESIGN.md`에서 인상과 색, 타이포그래피를 정한다
3. `DESIGN-SPEC.md`로 화면을 잡고 `prompts/CLAUDE-DESIGN-PROMPT.md`로 시안을 만든다
4. `SPEC.md`에 동작 규칙을 적는다. 화면이 보이면 규칙이 구체적으로 적힌다
5. `ROADMAP.md`에서 범위를 만들 순서로 자른다

파비콘과 로고, OG 이미지처럼 배포되는 이미지 파일은 브랜드 색이 정해진 뒤에 `prompts/IMAGE-ASSET-PROMPT.md`를 채운다.

각 문서 첫머리의 안내 문단과 채우는 요령은 내용을 채우면서 지운다. 골격만 보일러플레이트의 것이고 내용은 프로젝트의 것이다.

## 새 문서를 추가할 때

기존 파일의 절로 먼저 넣는다. 파일이 길어져 찾기 어렵거나 읽는 사람이 달라지면 그때 분리하고, 분리하면 위 표에 한 줄 추가한다.
