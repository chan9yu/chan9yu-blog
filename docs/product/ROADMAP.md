# chan9yu 개발 블로그 로드맵

무엇을 어떤 순서로 만드는지 적는다. PRD.md의 범위를 작업 순서로 자른 것이다.

첫 공개까지는 마일스톤 단위로 만들었고, 공개 뒤로는 릴리스 사이클로 굴린다. 지금은 릴리스 사이클이다.

## 지난 마일스톤

첫 공개까지의 기록이다. M0부터 M7까지 전부 끝났고 v1.1.0으로 프로덕션에 처음 올라갔다. 이후 작업은 이 번호를 이어 쓰지 않는다.

| 마일스톤                 | 목표                                  | 포함 기능                                                    | 태스크 | 상태 |
| ------------------------ | ------------------------------------- | ------------------------------------------------------------ | ------ | ---- |
| M0 Foundation            | 모든 라우트가 빈 페이지로 렌더되는 쉘 | 디자인 토큰, 공통 레이아웃, 라우팅 쉘 14종                   | 33     | 완료 |
| M1 UI Skeleton           | 더미 데이터로 전 페이지 UI 완성       | 홈부터 About까지 전 화면, 검색 모달, 테마, 라이트박스        | 61     | 완료 |
| M2 Content Pipeline      | 실제 MDX 콘텐츠 렌더                  | 서브모듈, frontmatter 파싱, 읽기 시간, 이미지 복사, MDX 렌더 | 24     | 완료 |

개발 순서는 Page-First Skeleton 원칙을 따랐다. M1에서 전 페이지를 더미 데이터로 먼저 완성해 UX 흐름을 확정하고, M2부터 M4에서 콘텐츠와 기능, 집계를 단계적으로 실데이터로 교체했다.

## v1.3.0 재작성

기능을 v1.2.0과 같게 유지하면서 코드를 처음부터 다시 세웠다. 화면에 보이는 기능은 그대로고 바뀐 것은 구조와 겉모습, 무엇에 기대는지다. 갈래별 결과를 아래에 남기고 끝내지 못한 항목은 다음 릴리스 후보로 넘겼다.

| 갈래                 | 결과                                                                                                                                                                                                                       |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 안전망 복구          | 지워져 있던 e2e 스펙 5종과 playwright 설정, `test:e2e` 스크립트를 되살렸다. 대화상자 접근성 스펙 2종이 더해져 지금은 7종이다                                                                                               |
| 죽은 코드 제거       | 참조가 0인 컴포넌트 6개와 쓰이지 않던 keyframe, 토큰, 데이터 함수를 지웠다                                                                                                                                                 |
| FSD 2.0 전환         | 3계층을 FSD 여섯 레이어로 옮겼다. 라우팅은 루트 `app/`이 맡고 구현은 `src/`에서 재노출한다. 레이어 경계는 eslint 내장 no-restricted-imports와 Steiger가 막는다. eslint는 lefthook 커밋 훅이, Steiger는 CI가 돌린다         |
| 디자인 토큰          | 다크 모드 회색 계열과 타입 스케일을 하나로 통일하고 본문 폭 44rem과 반응형 본문 크기를 걸었다                                                                                                                              |
| 프리미티브 직접 구현 | `Button`과 `Dialog`, `Drawer`를 직접 만들었다. `Dialog`는 네이티브 `dialog` 요소의 `showModal` 기반이다. 복사 알림은 `ShareButtons` 안 인라인 구현이고 대화상자 접근성 7항목은 검색 모달과 모바일 서랍 각각 e2e로 증명했다 |
| 디자인 개편          | 태그 칩을 한 모양으로 통일하고 좁은 화면에서 사라지던 사이드바와 태그 목록의 대안을 넣었다. 카드 등장은 CSS 스크롤 타임라인으로, 페이지 이동은 View Transitions로 처리하고 테마 전환 경로를 하나로 정리했다                |
| SEO 보강             | 라우트별 메타데이터와 JSON-LD 4종을 재확인하고 `/og`에 Pretendard를 넣었다. 뱃지 팔레트를 토큰과 잇고 SEO 규약을 `.agents/rules/`에 다시 세웠다                                                                            |
| 의존성 정리          | radix-ui와 class-variance-authority, sonner, tw-animate-css, shadcn을 지웠다. `@tailwindcss/typography`는 넣지 않았고 자체 `prose.css`가 본문 조판을 맡는다                                                                |
| 하네스 재구성        | 위험 기준으로 나눈 에이전트 4명과 스킬 4종을 세우고 no-fallback과 comments 룰을 되살렸다. 팀 통신은 Orca 다중 작업자로 확인했다                                                                                            |

## 다음 릴리스 후보

v1.3.0에서 이월한 항목이다.

- [ ] CI 워크플로우에 ESLint 단계를 넣는다. FSD 경계는 Steiger가 CI에서 잡지만 나머지 lint 규칙은 lefthook 커밋 훅에서만 돈다
- [ ] 임의값 사용처를 토큰 유틸로 바꾼다. `px-[9px]`와 `h-[26px]`, `scale-[0.98]` 같은 사용처가 남아 있다
- [ ] 여섯 폭 구간과 라이트, 다크 조합으로 전 화면을 확인한다
- [ ] `android-chrome-512x512.png`를 만들어 manifest에 등록한다. 원본이 될 심볼 마크(`logo-mark.svg`)가 아직 없다
- [ ] 하네스를 실제로 돌려 스킬과 에이전트가 조건에 맞을 때 불려 나오는지 확인한다
- [ ] Playwright e2e를 CI에서 돌린다. 직접 만든 대화상자와 서랍의 접근성 검증 16개가 로컬 수동 실행에 매달려 있다. 콜드 dev 서버의 첫 컴파일이 테스트 timeout을 넘기므로 webServer를 프로덕션 빌드로 바꾸는 조정이 함께 필요하다
