## v1.3.0 작업 계획

기능을 늘리지 않고 코드를 다시 세운다. 화면에 보이는 기능은 v1.2.0과 같아야 하고, 바뀌는 것은 구조와 겉모습, 그리고 무엇에 기대고 있는지다.

기능이 그대로라는 점이 이 릴리스의 안전장치다. 어떤 변경이든 "전과 똑같이 동작하는가"로 판정할 수 있다.

### 갈래

여섯 갈래다. 서로 얽힌 정도가 달라서 순서가 중요하다.

| 갈래          | 무엇을                                     | 규모               |
| ------------- | ------------------------------------------ | ------------------ |
| FSD 2.0 전환  | 3계층 자체 구조를 FSD 표준 레이어로 옮긴다 | 파일 166개 이동    |
| shadcn 제거   | 프리미티브 3개를 직접 만들고 4개를 지운다  | 신규 3개, 삭제 4개 |
| 디자인 개편   | 토큰과 타이포를 정리하고 화면에 적용한다   | 토큰과 전 화면     |
| 하네스 재구성 | 룰과 스킬을 `.agents/`에 다시 세운다       | 룰 1개에서 확장    |
| SEO 보강      | 메타데이터와 구조화 데이터를 다시 본다     | 라우트 전체        |
| 의존성 정리   | 쓰지 않는 것을 뺀다                        | 4개 제거 예상      |

### 순서

**한 커밋은 한 종류의 변경만 담는다.** 위치를 옮기는 커밋과 내용을 바꾸는 커밋을 섞으면 무엇이 깨뜨렸는지 가려낼 수 없다. 아래 순서는 그 원칙에서 나온다.

1. **안전망을 먼저 세운다.** 지금 e2e 테스트가 작업 트리에서 지워져 있다. 구조를 통째로 옮기는 작업에서 회귀를 잡아줄 것이 없다
2. **죽은 코드를 먼저 지운다.** 옮길 대상을 줄인 다음에 옮긴다. 지울 파일을 옮기는 것은 낭비다
3. **FSD 전환은 순수 이동으로 한다.** 파일 위치와 import 경로만 바꾸고 내용은 손대지 않는다. 이 단계에서 동작이 바뀌면 이동 중 실수다
4. **그다음 내용을 바꾼다.** 토큰을 정리하고 프리미티브를 만들고 화면에 적용한다
5. **마지막에 청소한다.** 의존성은 지워도 되는 상태가 된 뒤에 지운다

하네스 재구성은 나머지와 얽히지 않는다. 언제 해도 되고 먼저 해두면 이후 작업이 편해진다.

### 1. 안전망 복구

- [ ] `playwright.config.ts`와 `e2e/` 5개 스펙을 되살린다
- [ ] 되살린 e2e가 현재 코드에서 통과하는지 확인한다
- [ ] `package.json`에 `test:e2e` 스크립트를 되돌린다

되살릴 스펙은 홈에서 글 상세로 이동, Cmd+K 검색, 목차 클릭 스크롤, 테마 전환 유지, 모바일 서랍이다. 공교롭게도 이 다섯이 v1.3.0에서 가장 크게 손대는 곳과 겹친다.

### 2. 죽은 코드 제거

참조가 0인 것을 확인했다.

- [ ] `shared/components/ui/`에서 `Accordion`, `Badge`, `DropdownMenu`, `Sonner` 삭제
- [ ] `shared/components/common/`에서 `FadeInWhenVisible`, `PageTransition` 삭제
- [ ] 쓰이지 않는 keyframe 5종 삭제 (`fade-in-up`, `scale-in`, `slide-in-left`, `slide-in-right`, `pulse-subtle`, `shimmer`)
- [ ] 쓰이지 않는 토큰 삭제 또는 연결 (`--shadow-accent`, `success`와 `warning`, `info` 계열, `--color-text-disabled`, `--radius-xl`, z-index 4종)
- [ ] `getPostBySlug`와 `getBatchPostViews`, `TrendingSnapshot` 타입 정리

z-index 토큰은 정의만 있고 코드는 `z-30`처럼 숫자를 직접 쓴다. 토큰을 살려 숫자를 대체하거나 토큰을 지운다. 둘 중 하나를 고른다.

### 3. FSD 2.0 전환

FSD는 7개 레이어를 정의하고 위 레이어가 아래 레이어만 참조하게 한다. Next.js와 함께 쓸 때는 FSD의 `app`과 `pages`를 `_app`과 `_pages`로 바꿔 프레임워크 폴더와 이름이 겹치지 않게 하고, Next의 `src/app`은 재노출만 한다.

현재 3계층을 이렇게 나눈다.

| 현재                                                        | FSD 레이어 | 근거                                   |
| ----------------------------------------------------------- | ---------- | -------------------------------------- |
| `features/posts`, `tags`, `series`의 데이터와 카드          | `entities` | 도메인 모델이다. 여러 화면이 함께 쓴다 |
| `features/search`, `views`, `theme`, `lightbox`, `comments` | `features` | 사용자가 하는 동작이다                 |
| `Header`, `Footer`, `Sidebar`, `Toc`, `PostList`            | `widgets`  | 여러 조각을 묶은 화면 단위다           |
| 페이지별 조립                                               | `_pages`   | 라우트 하나에 대응한다                 |
| `shared/*`                                                  | `shared`   | 도메인을 모른다                        |

- [ ] `entities/post`, `entities/tag`, `entities/series` 신설. 데이터 접근과 도메인 UI를 옮긴다
- [ ] `features/`를 사용자 동작 단위로 재편한다
- [ ] `widgets/` 신설. 화면 단위 묶음을 옮긴다
- [ ] `_pages/` 신설. `src/app`의 페이지 구현을 옮기고 라우트 파일은 재노출만 남긴다
- [ ] 각 슬라이스에 `ui`, `model`, `api`, `lib` 세그먼트를 적용한다
- [ ] `eslint-plugin-boundaries` 또는 import 제한 규칙으로 레이어 위반을 CI에서 막는다

**이 단계에서 확인할 것.** 옮기기 전과 후의 빌드 산출물이 같아야 한다. 페이지가 늘거나 줄면 이동 중 무언가 빠진 것이다.

**갈림길 하나.** 지금 `features/posts`는 데이터 접근과 카드 UI, 목록 위젯이 한 디렉토리에 섞여 있다. FSD로 가면 셋이 세 레이어로 흩어진다. 파일 31개가 가장 크게 쪼개지는 자리다. 여기부터 손대고 나머지를 따라 맞추는 편이 낫다.

### 4. 디자인 토큰과 타이포 정리

DESIGN.md가 정한 값으로 맞춘다.

- [ ] 다크 모드 회색 계열을 하나로 통일한다. 지금 표면은 zinc, 텍스트는 slate다
- [ ] 타입 스케일을 하나로 정한다. 지금 토큰 10단계와 Tailwind 기본 스케일이 병존하고 실사용은 후자다
- [ ] 본문 폭 44rem을 실제로 건다. 지금 토큰은 있으나 본문에 `max-w-none`이 걸려 무효다
- [ ] 반응형 본문 크기를 살린다. `prose-sm`과 `sm:prose-base`, `md:prose-lg`가 플러그인 부재로 동작하지 않는다
- [ ] 임의값 사용처를 토큰 유틸로 바꾼다

본문 폭과 본문 크기 둘이 가독성에 가장 직접 걸린다. 다른 것보다 먼저 한다.

### 5. shadcn 제거와 프리미티브 직접 구현

남은 것은 셋뿐이다. 각각 한 곳에서만 쓰인다.

- [ ] `Button` 직접 구현. variant는 CVA 대신 매핑 객체로
- [ ] `Dialog` 직접 구현. 검색 모달과 라이트박스가 쓴다
- [ ] `Sheet` 직접 구현. Dialog 위에 방향과 슬라이드만 얹는다
- [ ] `FocusTrap`을 만들어 Dialog와 Sheet가 공유하게 한다
- [ ] `Toast`를 아주 작게 만든다. 지금 쓰는 곳은 복사 알림 하나다
- [ ] 대화상자 접근성 점검 목록 7가지를 테스트로 증명한다

**가장 위험한 지점이다.** Radix가 대신 해주던 것을 빼먹으면 접근성이 조용히 무너진다. 포커스 가두기, 닫을 때 포커스 복원, `aria-modal`, ESC, 배경 스크롤 잠금, 바깥 클릭, 뒤 배경 감추기 일곱이다. 눈으로 보면 멀쩡해 보이므로 테스트로 잡는다.
