# chan9yu 개발 블로그 PRD

무엇을 왜 만드는지 합의하는 문서다. 범위가 바뀌면 코드보다 이 문서를 먼저 고친다.

## 한 줄 정의

한국어권 프론트엔드 엔지니어가 검색이나 시리즈 링크로 도착해 React와 TypeScript, Next.js, WebRTC 실무 문제의 답을 찾으려고 여는 1인 저자 기술 블로그다.

## 문제

저자는 실무에서 배운 것을 파편적인 메모가 아니라 완결된 포스트와 이어지는 시리즈로 기록하고 싶다. velog나 tistory 같은 플랫폼 블로그가 기존 대안이지만 도메인과 마크업, 메타데이터를 플랫폼이 소유해서 SEO와 성능을 직접 통제할 수 없고, 조회수 집계나 GitHub README 뱃지 같은 커스텀 기능을 붙일 수 없다. 독자 입장에서는 검색으로 도착한 한국어 기술 글이 대부분 단편이라 한 주제를 순서대로 따라갈 학습 경로가 드물다.

## 사용자

React와 Next.js, TypeScript를 실무에서 쓰는 한국어권 프론트엔드 개발자다. 검색 엔진에서 특정 문제를 들고 도착하거나 시리즈 링크로 유입되어 한 주제를 이어서 읽는다. 저자 자신도 사용자다. 과거 글을 다시 찾고 포트폴리오 링크로 공유한다.

## 핵심 가치

한 주제를 시리즈로 끝까지 따라갈 수 있는 완결성이다. 단편 팁 대신 순서가 있는 시리즈와 태그, 관련 글 연결로 다음 글이 자연스럽게 이어지고, 정적 생성 기반이라 어떤 기기에서도 지연 없이 읽힌다.

## 범위

### 넣는 것

전부 구현되어 프로덕션(www.chan9yu.dev)에서 동작 중이다. 상세 동작은 SPEC.md가 정의한다.

| 기능             | 한 줄 설명                                                     |
| ---------------- | -------------------------------------------------------------- |
| 발행 파이프라인  | MDX 커밋과 푸시만으로 발행, frontmatter 위반은 빌드 실패       |
| 홈               | 최근 포스트 6편과 인기 포스트, 인기 시리즈, 인기 태그 사이드바 |
| 포스트 목록      | 전체 공개 글을 격자와 리스트로 보는 무한 스크롤 목록           |
| 포스트 상세      | MDX 본문과 목차, 읽기 진행률, 코드 하이라이트, 관련 글 연결    |
| 태그             | 태그 허브와 태그별 글 목록, 한글 태그 지원                     |
| 시리즈           | 시리즈 허브와 순서 있는 글 목록, 글 안의 시리즈 이동           |
| 검색             | Cmd+K 모달에서 제목과 설명, 태그 퍼지 검색                     |
| 조회수           | 글별 조회수 표시와 세션당 1회 집계                             |
| 댓글             | giscus 기반 GitHub Discussions 댓글                            |
| 테마             | 라이트와 다크 전환, 시스템 설정 따름                           |
| 라이트박스       | 본문 이미지 확대와 좌우 넘기기                                 |
| 공유             | Web Share 또는 링크 복사                                       |
| About            | 저자 소개와 소셜 링크                                          |
| SEO와 신디케이션 | 메타데이터와 JSON-LD, 동적 OG 이미지, sitemap, RSS, robots     |
| README 뱃지      | GitHub 프로필에 최근 글 카드 이미지 노출                       |

### 넣지 않는 것

| 기능                       | 빼는 이유                                         |
| -------------------------- | ------------------------------------------------- |
| 다중 저자, 승인 워크플로우 | 1인 운영이라 권한 관리가 필요 없다                |
| 회원가입, 로그인           | 댓글은 giscus의 GitHub 로그인으로 위임한다        |
| 결제, 유료 구독            | 블로그 자체로 수익화할 계획이 없다                |
| 이메일 뉴스레터            | 1인 운영 비용 대비 효과가 낮다. 필요해지면 재검토 |
| 실시간 기능(알림, 채팅)    | 제품 성격과 맞지 않는다                           |
| 서버 사이드 풀텍스트 검색  | 수백 편 규모까지는 클라이언트 fuse.js로 충분하다  |
| 다국어                     | 한국어 단일 locale                                |
| 관리자 UI, CMS             | MDX 파일과 Git 워크플로우로 충분하다              |
| 오프라인 지원              | Service Worker 복잡도 대비 이득이 없다            |
| 네이티브 앱                | 모바일 웹으로 충분하다                            |
| 클라이언트 캐시 라이브러리 | 런타임 서버 상태가 조회수 하나뿐이다              |

## 성공 기준

Vercel Analytics와 Speed Insights, Google Search Console로 잰다.

- 월간 순 방문자 2,000명 이상
- 공개 포스트 40편 이상 (2026-08-20 기준 26편)
- 대표 포스트의 검색 유입이 전체 유입의 절반 이상
- Core Web Vitals 세 지표(LCP 2.5초, CLS 0.1, INP 200ms) 전부 통과
- 모든 공개 포스트가 Google에 색인
