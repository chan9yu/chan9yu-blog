# chan9yu 개발 블로그 기능 명세

기능이 정확히 어떻게 동작하는지 적는 문서다. 왜 만드는지는 PRD.md가 맡는다. 구현하다 규칙이 바뀌면 이 문서를 먼저 고치고 코드를 맞춘다.

## 용어

| 용어           | 뜻                                                  | 코드에서                      |
| -------------- | --------------------------------------------------- | ----------------------------- |
| 포스트         | `contents/posts/{slug}/index.mdx` 한 편             | `PostSummary`, `PostDetail`   |
| frontmatter    | 포스트 머리의 YAML 메타데이터                       | `PostFrontmatterSchema` (zod) |
| 공개 포스트    | private가 아닌 포스트. 모든 노출과 집계의 대상      | `getPublicPosts()`            |
| private 포스트 | 목록, 검색, sitemap, RSS, 집계 전부에서 제외되는 글 | `frontmatter.private`         |
| 시리즈         | series와 seriesOrder로 연결된 포스트 묶음           | `Series`, `getAllSeries()`    |
| 태그           | 포스트 분류 라벨. 한글 허용                         | `TagCount`, `getAllTags()`    |
| 읽기 시간      | 본문 길이로 계산한 예상 읽기 분                     | `readingTimeMinutes`          |
| 표시명 변환    | 한글 slug의 하이픈을 공백으로 되돌린 표시 이름      | `formatLocalizedSlug()`       |
| 조회수 키      | KV에 글별 조회수를 저장하는 키                      | `views:post:{slug}`           |
| 뱃지           | GitHub README에 넣는 최근 글 카드                   | `/badge/recent` 라우트        |

## 기능 상세

### 콘텐츠 파이프라인

**동작 규칙.** 저자가 contents 서브모듈(비공개 저장소 dev-blog-archive)의 `posts/{slug}/index.mdx`에 글을 쓰고 커밋, 푸시하면 배포 빌드가 발행을 끝낸다. 빌드 전에 두 스크립트가 돈다. `validate-frontmatter-seo.mjs`는 title 60자 이내, description 120~160자, slug 형식과 디렉토리명 일치를 검사해 위반 시 빌드를 중단한다. `copy-content-images.mjs`는 `contents/posts/{slug}/images/`를 `public/posts/{slug}/images/`로 복사한다. 변경된 파일만 복사하고 원본이 사라진 디렉토리는 정리한다.

**frontmatter.** zod 스키마 `PostFrontmatterSchema`가 단일 진실 공급원이다.

| 필드                | 필수 | 규칙                                          |
| ------------------- | ---- | --------------------------------------------- |
| title               | 필수 | 1자 이상, SEO 게이트에서 60자 이내            |
| description         | 필수 | SEO 게이트에서 120~160자                      |
| slug                | 필수 | 영문 소문자와 숫자, 하이픈. 디렉토리명과 일치 |
| date                | 필수 | ISO 8601                                      |
| updated             | 선택 | 수정일. sitemap lastmod에 반영                |
| private             | 선택 | 기본 false                                    |
| tags                | 선택 | 기본 빈 배열. 한글 허용                       |
| thumbnail           | 선택 | `/posts/{slug}/images/` 경로                  |
| series, seriesOrder | 선택 | 함께 설정하거나 함께 생략                     |

**경계 조건.** `@`로 시작하는 디렉토리(`@template`)는 스캔에서 제외된다. Vercel 빌드는 `STRICT_FRONTMATTER=1`이라 frontmatter 위반이 빌드 실패가 되고, 로컬 일반 빌드는 경고 후 해당 글만 건너뛴다.

**데이터.** 빌드 타임에 파일시스템에서 읽는다. `getPublicPosts()`는 React cache로 감싸 렌더 트리당 한 번만 스캔한다. 런타임에는 contents를 읽지 않는다. v1.1.2 프로덕션 장애 이후의 원칙이다.

### 홈

**동작 규칙.** 본문에 인사말(고정 텍스트)과 최근 공개 포스트 6편, 우측 사이드바에 인기 포스트 5편과 인기 시리즈 3개, 인기 태그 10개를 보여준다. 인기 포스트는 KV 누적 조회수 내림차순, 인기 시리즈는 소속 글 수 내림차순에 동률이면 최근 갱신 우선, 인기 태그는 글 수 내림차순이다.

**화면 흐름.** `/`. 카드는 `/posts/{slug}`로, 전체 보기는 `/posts`로, 사이드바 항목은 각 상세로 간다.

**경계 조건.** KV가 없거나 실패하면 인기 포스트는 최신순으로 대체된다. 사이드바는 lg 미만 화면에서 숨긴다.

**데이터.** revalidate 3600으로 1시간마다 재생성되고 그 시점의 KV 조회수를 반영한다. 재생성 주기를 가진 페이지는 홈뿐이다.

### 포스트 목록

**동작 규칙.** 전체 공개 글을 날짜 내림차순으로 12개씩 무한 스크롤(IntersectionObserver)로 보여준다. 격자와 리스트 뷰를 토글할 수 있고 기본은 격자다. 선택은 localStorage(`blog:posts:view`)에 저장된다.

**화면 흐름.** `/posts`. 좌측 태그 사이드바를 클릭하면 `/tags/{tag}`로 이동한다.

**경계 조건.** 0건이면 "조건에 맞는 포스트가 없습니다"를 보여준다. 서버 렌더는 격자로 고정하고 hydration 후 저장된 뷰를 적용해 서버와 클라이언트 렌더 불일치를 막는다.

**데이터.** 빌드 타임 prerender.

### 포스트 상세

**동작 규칙.** 위에서 아래로 메타 헤더(제목, 설명, 날짜, 조회수, 태그, 공유 버튼), 시리즈 네비게이션(소속 글만), 썸네일, MDX 본문, 이전과 다음 글 카드, 관련 글 3편(태그 겹침 수 기준), 댓글 순서다. 상단에 읽기 진행률 바가 있고, 데스크톱 우측에 접을 수 있는 sticky 목차, 모바일은 좌하단 버튼으로 여는 바텀시트 목차가 있다. 코드 블록은 Shiki가 서버에서 하이라이트하고 복사 버튼이 붙는다. heading에는 자동으로 앵커 id가 붙는다. 읽기 시간은 한국어 500자/분 기준으로 코드 블록과 이미지를 제외하고 계산하며 최소 1분이다.

**화면 흐름.** `/posts/{slug}`. 목차 항목을 클릭하면 헤더 높이만큼 보정해 스크롤하고 URL hash를 바꾼다. 공유 버튼은 Web Share API를 열고, 지원하지 않으면 링크를 복사하고 2초 안내를 띄운다.

**경계 조건.** 없는 slug는 404이고 metadata도 noindex다. private 글은 직접 URL로 열면 200으로 렌더하되 noindex 처리하고 JSON-LD를 생략하며 댓글을 렌더하지 않는다. 조회수는 Suspense placeholder에서 숫자로 교체되고 실패하면 숫자 대신 대시를 표시한다.

**데이터.** 모든 공개 slug를 `generateStaticParams`로 prerender한다. 런타임 데이터는 조회수 하나다.

### 태그

**동작 규칙.** 허브는 태그 카드 그리드(태그명과 글 수), 상세는 해당 태그의 글 목록이다. 목록은 포스트 목록의 무한 스크롤을 재사용한다. 태그는 한글을 허용하고 slug의 하이픈은 표시할 때 공백으로 되돌린다.

**화면 흐름.** `/tags`에서 `/tags/{tag}`로. 글 상세의 태그 칩에서도 진입한다. 한글 태그는 URL에서 percent 인코딩된다.

**경계 조건.** 태그가 하나도 없으면 허브에 빈 안내를 보여준다. 존재하지 않는 태그 상세는 404다.

**데이터.** frontmatter의 tags 집계. 빌드 타임 prerender.

### 시리즈

**동작 규칙.** 허브는 시리즈 카드다. 시리즈명과 총 글 수, 앞 3편 미리보기를 보여주고 초과분은 "+N개 더보기"로 줄인다. 상세는 seriesOrder 오름차순 번호 목록이다. 글 상세 안 시리즈 네비게이션은 시리즈명과 현재 순번, 전체 편수, 시리즈 안 이전과 다음 글, 전체 보기 링크를 보여준다.

**화면 흐름.** `/series`에서 `/series/{slug}`로. 글 상세의 시리즈 네비게이션에서도 진입한다.

**경계 조건.** 시리즈가 없으면 허브에 빈 안내를 보여준다. series와 seriesOrder가 모두 있는 글만 시리즈로 묶인다.

**데이터.** frontmatter 집계. slug는 frontmatter의 series 문자열 그대로다. 빌드 타임 prerender.

### 검색

**동작 규칙.** 헤더 버튼 또는 Cmd+K(Windows는 Ctrl+K)로 모달을 연다. 입력은 200ms 디바운스 후 fuse.js 퍼지 검색으로 최대 10건을 보여준다. 가중치는 제목 0.5, 설명 0.3, 태그 0.2다. 화살표 키로 결과를 순환하고 매칭 구간은 하이라이트된다.

**화면 흐름.** 어느 페이지에서든 열린다. 결과 클릭이나 Enter로 글 상세로 이동하며 모달이 닫힌다. ESC로 닫는다.

**경계 조건.** 빈 입력이면 인기 태그 5개와 최근 글 3편을 추천한다. 0건이면 안내를 보여준다. 본문은 검색 대상이 아니다. 제목과 설명, 태그만 찾는다.

**데이터.** 루트 layout이 서버에서 공개 글 요약 배열을 내려주고 클라이언트가 메모리에서 인덱스를 만든다. 별도 인덱스 파일은 없다. 모달과 fuse.js는 동적 import로 초기 번들에서 제외된다.

### 조회수

**동작 규칙.** 글 진입 시 sessionStorage로 세션당 1회만 `POST /api/views`를 보내 1 올리고, GET으로 현재 값을 받아 표시한다.

**화면 흐름.** 글 상세 메타 헤더 안에서만 보인다.

**경계 조건.** slug 검증(소문자와 숫자, 하이픈, 120자 이내)에 실패하면 400이다. KV가 설정되지 않았으면 GET은 0을 돌려주고 POST는 아무것도 하지 않는다. KV 오류도 응답은 정상 코드로 유지하고 콘솔 경고만 남긴다. 표시에 실패하면 숫자 대신 대시를 보여준다.

**데이터.** Vercel KV 키 `views:post:{slug}`. 응답은 no-store.

### 댓글

**동작 규칙.** giscus 스크립트를 직접 주입해(별도 npm 패키지 없음) GitHub Discussions와 연결한다. 매핑은 `posts/{slug}` 고정 문자열이다. 뷰포트 200px 전에 lazy 마운트되고 테마 전환 시 iframe에 postMessage로 테마를 동기화한다.

**화면 흐름.** 글 상세 최하단.

**경계 조건.** giscus 환경변수 4종 중 하나라도 없으면 안내 문구를 보여준다. private 글에는 렌더하지 않는다.

**데이터.** GitHub Discussions에 저장된다. 블로그는 저장하지 않는다.

### 테마

**동작 규칙.** next-themes 클래스 기반이고 기본값은 시스템 설정이다. 전환 시 View Transitions API를 지원하는 브라우저에서는 전환 애니메이션이 적용된다.

**화면 흐름.** 헤더 우측 토글 버튼.

**경계 조건.** hydration 전에는 투명 placeholder 아이콘을 렌더해 깜빡임과 레이아웃 이동을 막는다. 시스템의 모션 축소 설정을 따른다.

**데이터.** localStorage.

### 라이트박스

**동작 규칙.** 본문 이미지를 클릭하면 같은 글 안의 이미지 전부를 모아 carousel로 연다. 좌우 버튼과 화살표 키로 순환 이동하고 슬라이드 애니메이션이 붙는다. ESC나 배경 클릭으로 닫는다.

**화면 흐름.** 글 상세 본문 이미지에서만 열린다.

**경계 조건.** 작은 이미지는 원본 크기를 유지하고 큰 이미지만 화면의 90% 한도로 축소한다.

**데이터.** 없음. 컴포넌트는 동적 import로 지연 로드된다.

### About

**동작 규칙.** 프로필(GitHub 아바타)과 이름, 직무, 소셜 링크를 보여주고 `contents/about/index.md`를 본문으로 렌더한다. Person JSON-LD를 함께 넣는다.

**화면 흐름.** `/about`.

**경계 조건.** about 파일이 없으면 빌드가 실패한다. 무음 대체는 없다.

**데이터.** 빌드 타임에 파일을 읽는다.

### SEO와 신디케이션

**동작 규칙.** 모든 페이지가 `buildMetadata` 공통 헬퍼로 title과 description, canonical, OG, Twitter 카드를 만든다. JSON-LD는 4종이다. WebSite는 루트에, BlogPosting과 BreadcrumbList는 글 상세에, BreadcrumbList는 태그와 시리즈 상세에, Person은 About에 넣는다. `/og`는 title, tag, thumbnail 파라미터로 1200x630 이미지를 동적 생성하고 thumbnail이 지정되면 302로 원본에 넘긴다. sitemap은 공개 글과 태그, 시리즈 전부를 포함하고 lastmod는 updated 또는 date다. RSS는 최신 50편의 RSS 2.0 XML이고 정적 생성에 s-maxage 3600 캐시다. robots는 프로덕션 외 환경에서 전체 차단하고, 프로덕션에서는 `/api/`만 차단하며 sitemap URL을 안내한다.

**경계 조건.** private 글은 sitemap, RSS, 검색, 관련 글, 인접 글, 태그와 시리즈 집계 전부에서 빠진다.

**데이터.** 전부 빌드 타임이다. `/og`만 요청 시 동적이다.

### README 뱃지

**동작 규칙.** `/badge/recent/{index}`(0부터 5)는 N번째 최신 공개 글로 302 리다이렉트한다. `/badge/recent/{index}/{theme}`(dark 또는 light)는 480x440 PNG 카드를 돌려준다. 카드는 썸네일(16:9)과 제목 2줄, 날짜로 구성되고 썸네일이 없으면 브랜드 표시로 대체한다. GitHub README에는 picture 태그와 prefers-color-scheme으로 라이트와 다크를 자동 교체해 넣는다.

**화면 흐름.** 블로그 화면이 아니라 GitHub 프로필 README에서 소비된다.

**경계 조건.** 범위 밖 index나 잘못된 theme은 404다. GitHub 이미지 캐시(Camo) 특성상 새 글 반영까지 몇 시간 걸릴 수 있다.

**데이터.** 빌드 타임에 index와 theme 전 조합을 prerender한다(dynamicParams false). 캐시는 s-maxage 3600에 stale-while-revalidate 86400이다. 한글 렌더용으로 Pretendard 정적 OTF를 쓴다. Satori가 가변 폰트를 지원하지 않아서다.

## 운영

배포는 Vercel이다. `pnpm install:vercel`이 서브모듈 URL에 토큰을 주입해 clone하고, `pnpm build:vercel`은 `STRICT_FRONTMATTER=1`로 frontmatter 위반을 빌드 실패로 만든다.

| 환경변수                                                           | 없을 때 동작                        |
| ------------------------------------------------------------------ | ----------------------------------- |
| `NEXT_PUBLIC_GISCUS_REPO`, `_REPO_ID`, `_CATEGORY`, `_CATEGORY_ID` | 댓글 자리에 안내 문구               |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` 등 KV 계열                  | 조회수 0 표시, 인기 포스트는 최신순 |
| `GITHUB_REPO_CLONE_TOKEN`                                          | Vercel에서 서브모듈 clone 실패      |

품질 게이트는 두 겹이다. 커밋 전 lefthook이 eslint와 prettier, `tsc --noEmit`을 돌리고, CI는 타입 검사와 Vitest(41개 파일)를 돌린다.
