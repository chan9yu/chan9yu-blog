# 대화상자 접근성 검증

Radix가 대신하던 일이 사라졌는지 확인한다. 화면으로는 티가 나지 않는 자리다.

## 기준

WCAG 2.2 AA를 쓴다. WCAG 3.0은 아직 완성되지 않았고 APCA는 확정 표준이 아니므로 판정에 쓰지 않는다.

## 일곱 항목

항목마다 확인하는 방법이 다르다. 눈으로 보는 것으로는 대부분 통과처럼 보인다.

**1. 열릴 때 포커스가 안으로 들어가는가**

열고 나서 바로 Tab을 눌러 본다. 대화상자 안 요소로 가면 통과다. 페이지 맨 위 요소로 가면 실패다.

테스트로는 열린 직후 `document.activeElement`가 대화상자 안에 있는지 본다.

**2. Tab이 밖으로 새지 않는가**

안의 요소 개수보다 많이 Tab을 눌러 본다. 마지막 다음이 처음으로 돌아오면 통과다. 주소창이나 뒤 페이지로 가면 실패다.

Shift+Tab으로 반대 방향도 확인한다. 한쪽만 막힌 구현이 흔하다.

**3. 닫을 때 열었던 곳으로 돌아가는가**

열기 전에 어느 버튼에 포커스가 있었는지 기억하고, 닫은 뒤 Tab을 눌러 본다. 그 버튼 다음으로 가면 통과다. 페이지 처음부터 시작하면 실패다.

이걸 빠뜨리면 키보드 사용자는 닫을 때마다 위치를 잃는다.

**4. 역할과 이름이 붙었는가**

`role="dialog"`와 `aria-modal="true"`가 있는지, 제목 요소가 `aria-labelledby`로 연결됐는지 본다. 마크업을 읽으면 확인된다.

이름 없는 대화상자는 스크린 리더에서 "dialog"라고만 읽힌다.

**5. ESC로 닫히는가**

닫히는지 본다. 겹쳐 열 수 있는 곳이면(라이트박스 위에 무언가) 맨 위 하나만 닫히는지도 본다. 전역 리스너로 만들면 전부 닫힌다.

**6. 뒤가 스크롤되지 않는가**

열린 상태에서 마우스 휠을 굴리고 화살표를 눌러 본다. 뒤 페이지가 움직이면 실패다.

열 때 화면이 가로로 튀는지도 본다. 스크롤바가 사라지며 폭이 바뀌는 것을 보정하지 않으면 튄다.

**7. 뒤 배경이 보조 기술에서 감춰지는가**

바깥 형제 요소에 `aria-hidden="true"`가 붙었거나 `inert`가 걸렸는지 본다. 없으면 스크린 리더가 뒤 내용을 계속 읽는다.

## 추가로 보는 것

**바깥 클릭.** 대화상자 안에서 마우스를 누르고 밖에서 떼어 본다. 닫히면 실패다. 텍스트를 끌어 선택할 때 이 일이 생긴다.

**포커스 표시.** 안의 요소를 Tab으로 지나며 지금 어디에 있는지 보이는지 확인한다. 2px 두께에 배경 대비 3대 1 이상이어야 한다.

**터치 대상.** 닫기 버튼 같은 것이 44x44px 이상인지 본다. 아이콘이 작아도 클릭 영역은 커야 한다.

**모션 축소.** 시스템에서 모션 축소를 켜고 열어 본다. 위치를 옮기는 애니메이션이 죽는지 확인한다.

## 테스트로 만들기

눈으로 확인한 것은 다음 사람이 다시 확인해야 한다. 테스트로 남긴다.

확인하기 쉬운 것부터 쓴다. 포커스 위치와 속성 존재, 키보드 반응은 테스트가 쉽다. 스크린 리더 낭독은 어렵다.

```
열기 버튼을 누른 뒤 확인한다
  activeElement가 대화상자 안인가
  role과 aria-modal이 있는가
  body가 스크롤 잠겼는가

Tab을 요소 수보다 많이 누른 뒤 확인한다
  activeElement가 여전히 대화상자 안인가

ESC를 누른 뒤 확인한다
  닫혔는가
  activeElement가 열기 버튼인가
```

## 결과 내는 법

표로 낸다. 확인한 방법 칸을 비우지 않는다.

| 항목 | 판정 | 확인한 방법 | 실패면 무엇이 어긋났는지 |
| ---- | ---- | ----------- | ------------------------ |

**통과를 증명할 수 없으면 통과로 적지 않는다.** "구현했다"는 말은 근거가 아니다. 실행해서 확인하지 못한 항목은 "확인 못 함"으로 적고 무엇이 있으면 확인할 수 있는지 함께 적는다.

실패 항목에는 고칠 방향을 한 줄 붙이되 직접 고치지 않는다. 고치는 것은 만든 사람의 몫이다.

같은 항목이 세 번 실패하면 구현 방식 자체를 다시 보자고 보고한다. 네 번째 시도는 같은 이유로 실패한다.
