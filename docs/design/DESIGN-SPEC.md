# chan9yu 개발 블로그 화면 명세

화면마다 무엇이 어떻게 놓이는지 적는다. 톤과 색은 DESIGN.md가 정하고 이 문서는 배치와 상태를 정한다.

구간 이름(base, sm, md, lg, xl, 2xl)과 높이 구간은 DESIGN.md의 지원 범위 절에서 정의한 것을 그대로 쓴다.

## 화면 목록

Next.js App Router의 라우트 경로를 기준으로 적는다. `src/app` 아래 디렉토리와 하나씩 대응한다.

| 경로             | 화면 이름   | 목적                                    |
| ---------------- | ----------- | --------------------------------------- |
| `/`              | 홈          | 이 블로그의 성격과 최근 활동을 파악한다 |
| `/posts`         | 포스트 목록 | 전체 글을 훑어 읽을 것을 고른다         |
| `/posts/[slug]`  | 포스트 상세 | 글 한 편을 끝까지 읽는다                |
| `/tags`          | 태그 허브   | 관심 주제를 고른다                      |
| `/tags/[tag]`    | 태그 상세   | 한 주제의 글을 모아 본다                |
| `/series`        | 시리즈 허브 | 학습 경로를 고른다                      |
| `/series/[slug]` | 시리즈 상세 | 한 시리즈를 순서대로 본다               |
| `/about`         | About       | 저자를 알고 연락 경로를 찾는다          |
| 없는 경로        | 404         | 잘못 온 것을 알리고 되돌아갈 길을 준다  |

응답 전용 라우트(`/rss`, `/og`, `/sitemap.xml`, `/robots.txt`, `/api/views`, `/badge/recent`)는 화면이 아니므로 이 문서가 다루지 않는다. 동작은 product/SPEC.md가 정의한다.

## 공통 골격

모든 화면이 같은 골격을 쓴다. 위에서 아래로 본문 바로가기 링크, 헤더, 본문, 푸터다.

### 헤더

| 구간            | 배치                                                           |
| --------------- | -------------------------------------------------------------- |
| base에서 sm     | 로고, 검색 버튼, 테마 버튼, 햄버거 버튼. 네비 항목은 서랍 안에 |
| md 이상         | 로고, 네비 5개, 검색 버튼, 테마 버튼. 햄버거 없음              |
| 높이 480px 이하 | `sticky` 해제. 화면 높이를 본문에 준다                         |

배경은 80퍼센트 불투명에 뒤 배경을 흐린다. 경계선은 스크롤이 시작될 때 나타난다. 스크롤 타임라인을 지원하지 않는 브라우저에서는 경계선이 없고 그것으로 충분하다.

로고는 `<chan9yu />`이고 홈으로 간다. 네비 항목은 홈과 포스트, 시리즈, 태그, About이며 현재 경로가 강조된다.

### 푸터

본문에서 6rem 아래에 구분선을 두고 시작한다. 왼쪽에 블로그 이름과 소개 두 줄, 오른쪽에 RSS와 GitHub, 이메일 링크를 둔다. 그 아래 구분선 다음에 저작권 한 줄이다.

base와 sm에서는 좌우 두 블록이 위아래로 쌓인다.

배포 버전 배지는 화면 왼쪽 아래에 고정된다. md 미만에서는 숨긴다. 좁은 화면에서 본문을 가리기 때문이다.

### 본문 바로가기

첫 Tab에서 나타나는 링크다. 헤더를 건너뛰고 본문으로 간다. 평소에는 화면 밖에 있다.

## 화면 상세

### 홈 `/`

**목적.** 이 블로그가 무엇을 다루는지 알고 읽을 글 하나를 고른다.

**구성.** 위에서 아래로 인사말, 최근 포스트 6편, 사이드바(인기 글 5편, 인기 시리즈 3개, 인기 태그 10개)다. 인사말은 저자 소개 두 문단과 소셜 링크로 짧게 끝낸다. 최근 포스트 구역에는 제목과 전체 보기 링크를 나란히 둔다.

**상태.** 글이 6편보다 적으면 있는 만큼만 보여준다. 조회수 집계가 없으면 인기 글이 최신 글로 바뀌는데 표시는 달라지지 않는다.

**인터랙션.** 카드는 전체가 클릭 영역이다. hover에서 테두리가 액센트로 옅게 바뀌고 카드가 2px 떠오르며 썸네일이 1.05배로 커진다. 목록 뷰와 격자 뷰를 토글할 수 있고 선택은 저장된다.

**반응형.**

| 구간    | 배치                                                       |
| ------- | ---------------------------------------------------------- |
| base    | 1단. 카드 1열. 사이드바는 숨김                             |
| sm      | 1단. 카드 1열, 여백 확대                                   |
| md      | 1단. 카드 2열. 사이드바는 숨김                             |
| lg 이상 | 2단. 본문과 오른쪽 사이드바 16rem. 카드 2열, 사이드바 고정 |
| 2xl     | 위와 같고 좌우 여백만 증가                                 |

사이드바를 lg 미만에서 숨기는 현재 방식은 그 정보가 작은 화면에서 사라진다는 뜻이다. v1.3.0에서 본문 아래로 옮겨 접힌 상태로 두는 것을 검토한다.

### 포스트 목록 `/posts`

**목적.** 전체 글에서 읽을 것을 고른다.

**구성.** 페이지 제목과 설명, 왼쪽 태그 목록, 오른쪽 글 목록이다. 목록 위에 뷰 토글을 둔다.

**상태.** 12편씩 이어 붙이고 아래로 내리면 다음 12편이 붙는다. 0건이면 안내 문구를 보여준다. 서버가 그린 첫 화면은 항상 격자이고 저장된 선택은 그다음에 반영된다.

**인터랙션.** 카드 hover는 홈과 같다. 뷰를 바꾸면 카드가 제자리에서 새 배치로 미끄러진다. 태그를 누르면 태그 상세로 간다.

**반응형.**

| 구간        | 배치                                       |
| ----------- | ------------------------------------------ |
| base에서 sm | 1단. 카드 1열. 태그 목록은 숨김            |
| md          | 1단. 카드 2열. 태그 목록은 숨김            |
| lg 이상     | 2단. 왼쪽 태그 목록 16rem, 오른쪽 카드 2열 |

태그 목록도 lg 미만에서 사라진다. 목록에서 태그로 좁혀 들어가는 길이 작은 화면에 없다. v1.3.0에서 제목 아래 가로 스크롤 칩 줄로 대신 두는 것을 검토한다.

### 포스트 상세 `/posts/[slug]`

**목적.** 글 한 편을 방해 없이 끝까지 읽는다.

**구성.** 위에서 아래로 읽기 진행률 막대, 메타 헤더(제목, 설명, 날짜, 조회수, 태그, 공유), 시리즈 이동, 썸네일, 본문, 이전과 다음 글, 관련 글 3편, 댓글이다. 목차는 본문 옆이나 화면 아래 버튼에 있다.

**상태.** 조회수는 자리표시자에서 숫자로 바뀌고 실패하면 대시를 보여준다. 목차 항목이 없으면 목차를 숨긴다. 시리즈에 속하지 않으면 시리즈 이동을 렌더하지 않는다. 관련 글이 2편 미만이면 그 구역을 숨긴다. 비공개 글에는 댓글을 렌더하지 않는다.

**인터랙션.** 목차 항목을 누르면 헤더 높이만큼 띄워 부드럽게 이동하고 주소의 해시가 바뀐다. 읽는 위치의 항목이 강조된다. 코드 블록 오른쪽 위 버튼으로 복사하고 2초간 완료 표시가 뜬다. 본문 이미지를 누르면 전체 화면으로 열리고 좌우로 넘길 수 있다.

**반응형.**

| 구간            | 배치                                                 |
| --------------- | ---------------------------------------------------- |
| base에서 sm     | 1단. 목차는 화면 왼쪽 아래 버튼으로 열리는 바텀시트  |
| md              | 1단, 본문 폭 확대. 목차는 바텀시트 유지              |
| lg              | 2단. 본문과 오른쪽 고정 목차. 목차는 접을 수 있다    |
| xl 이상         | 위와 같고 본문 폭이 44rem에서 멈춘다. 남는 폭은 여백 |
| 높이 480px 이하 | 바텀시트 높이를 줄이고 목차 열기 버튼을 위로 올린다  |

본문 폭 상한은 v1.3.0에서 새로 거는 것이다. 지금은 목차를 접으면 본문이 남는 폭을 다 차지해 한 줄이 길어진다.

코드 블록은 어느 구간에서도 가로로 넘치지 않는다. 넘칠 때는 블록 안에서 가로 스크롤한다. 표도 같다. 페이지 본문 자체가 가로로 스크롤되면 안 된다.

### 태그 허브 `/tags`

**목적.** 관심 주제를 고른다.

**구성.** 페이지 제목과 태그 카드 격자다. 카드마다 태그 이름과 글 수를 보여준다.

**상태.** 태그가 없으면 안내 문구를 보여준다.

**인터랙션.** 카드 hover에서 테두리와 글자가 액센트로 바뀐다.

**반응형.** base 1열, sm 2열, md 3열, lg 이상 4열이다.

### 태그 상세 `/tags/[tag]`

**목적.** 한 주제의 글을 모아 본다.

**구성.** 경로 안내, 제목(태그 이름 앞에 `#`), 글 수, 글 목록이다. 목록은 포스트 목록과 같은 것을 쓴다.

**상태.** 해당 태그의 글이 없으면 404다.

**반응형.** 포스트 목록과 같되 왼쪽 태그 목록이 없어 1단이다. 카드는 md에서 2열이다.

### 시리즈 허브 `/series`

**목적.** 학습 경로를 고른다.

**구성.** 페이지 제목과 시리즈 카드 격자다. 카드마다 시리즈 이름과 전체 편수, 앞 3편 미리보기를 두고 남은 편수는 더보기 문구로 줄인다.

**상태.** 시리즈가 없으면 안내 문구를 보여준다.

**반응형.** base 1열, md 2열, lg 이상 3열이다. base에서는 미리보기를 2편으로 줄여 카드가 길어지지 않게 한다.

### 시리즈 상세 `/series/[slug]`

**목적.** 한 시리즈를 순서대로 읽는다.

**구성.** 경로 안내, 시리즈 이름, 전체 편수, 순서대로 번호가 붙은 글 목록이다. 목록은 순서 있는 목록으로 마크업한다.

**상태.** 없는 시리즈는 404다.

**인터랙션.** 항목 hover에서 배경이 옅게 바뀐다.

**반응형.** 모든 구간에서 1단 목록이다. base에서는 번호 배지를 제목 위로 올린다.

### About `/about`

**목적.** 저자가 누구인지 알고 연락 경로를 찾는다.

**구성.** 제목, 프로필 이미지, 이름과 직무, 소셜 링크, 마크다운 소개 본문이다.

**반응형.** base에서 프로필과 텍스트가 세로로 쌓이고 가운데 정렬이다. sm 이상에서 가로로 나란히 놓이고 왼끝 정렬이다. 본문은 어느 구간에서도 44rem을 넘지 않는다.

### 404

**목적.** 잘못 온 것을 알리고 되돌아갈 길을 준다.

**구성.** 큰 제목, 안내 한 줄, 홈으로 가는 버튼과 포스트 목록으로 가는 버튼이다.

**반응형.** 모든 구간에서 가운데 정렬 1단이다. base에서 버튼 두 개가 세로로 쌓이고 각각 폭을 가득 채운다.

## 공통 컴포넌트

두 화면 이상에서 쓰는 것만 적는다. 여기 있는 것은 블로그의 개념을 아는 패턴 층이다. 도메인을 모르는 프리미티브(버튼, 배지, 대화상자)의 목록과 구현 규칙은 DESIGN.md의 디자인 시스템 절에 있다.

| 컴포넌트      | 쓰는 화면                           | 규칙                                                                     |
| ------------- | ----------------------------------- | ------------------------------------------------------------------------ |
| 포스트 카드   | 홈, 포스트 목록, 태그 상세, 관련 글 | 모서리 0.75rem, 얇은 테두리, 그림자 약. hover에서 2px 상승과 썸네일 확대 |
| 태그 칩       | 카드 안, 태그 허브, 글 메타, 검색   | 알약 모양, 앞에 `#`. 최소 44x44px 터치 영역 확보                         |
| 뷰 토글       | 홈, 포스트 목록                     | 격자와 목록 두 상태. 선택은 저장되고 서버 렌더는 항상 격자               |
| 목록 스켈레톤 | 포스트 목록, 태그 상세              | 카드와 같은 높이. 레이아웃 이동을 만들지 않는다                          |
| 검색 모달     | 전체                                | 화면 위 10퍼센트에서 시작, 내용 높이는 화면의 60퍼센트 상한              |
| 라이트박스    | 포스트 상세                         | 큰 이미지는 화면의 90퍼센트로 축소, 작은 이미지는 원본 크기 유지         |
| 맨 위로 버튼  | 전체                                | 400px 넘게 내렸을 때 오른쪽 아래에 나타난다                              |

### 카드 태그와 태그 칩 통일

지금 두 가지 태그 표현이 있다. 카드 안 태그는 사각형에 외곽선이고 고정폭 글꼴이며, 태그 칩은 알약 모양에 채운 배경이고 본문 글꼴이다. 같은 것을 가리키는데 다르게 보인다. v1.3.0에서 하나로 맞춘다.

### 직접 구현으로 바뀌는 것

아래 넷은 지금 Radix에 얹혀 있다. v1.3.0에서 직접 만든 프리미티브 위로 옮긴다. 화면에 보이는 모습과 조작 방법은 그대로 두고 구현만 바뀐다.

| 패턴        | 지금 기반          | 옮겨 갈 곳       | 옮길 때 확인할 것                             |
| ----------- | ------------------ | ---------------- | --------------------------------------------- |
| 검색 모달   | Radix Dialog       | 직접 만든 Dialog | 입력창 자동 포커스, 화살표 순환, ESC          |
| 모바일 서랍 | Radix Dialog Sheet | 직접 만든 Sheet  | 열린 동안 배경 스크롤 잠금, 항목 선택 시 닫힘 |
| 라이트박스  | Radix Dialog       | 직접 만든 Dialog | 좌우 화살표 이동, 배경 클릭 닫힘              |
| 복사 알림   | 자체 div           | 직접 만든 Toast  | 보조 기술에 변경이 전달되는지                 |

옮긴 뒤 각 패턴이 DESIGN.md의 대화상자 점검 목록을 만족하는지 테스트로 확인한다. 지금은 Radix가 대신 해주던 부분이라 우리 테스트가 없다.

## 접근성 요구

WCAG 2.2 AA를 기준으로 한다. 화면을 만들 때 아래를 만족해야 한다.

- 모든 기능을 키보드만으로 쓸 수 있다. Cmd+K로 검색을 열고, Esc로 모달과 서랍, 라이트박스를 닫고, 좌우 화살표로 라이트박스를 넘긴다
- 포커스 표시는 2px 두께에 배경 대비 3대 1 이상이다
- 고정 헤더가 포커스된 요소를 가리지 않는다. 앵커 이동 지점에 헤더 높이만큼 여백을 둔다
- 모달과 서랍에서 포커스가 밖으로 나가지 않고, 닫으면 열었던 버튼으로 돌아온다
