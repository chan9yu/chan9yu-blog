# 주석

정본은 루트 `CLAUDE.md`의 "주석" 절이다. 여기서는 그 기준을 판단할 수 있을 만큼 풀어 적는다.

## 규칙

**기본은 주석을 쓰지 않는 것이다.** 코드가 스스로 말하지 못하는 것만 적는다. 넷이다.

| 무엇             | 왜 코드에 담기지 않는가                                    | 예                                                            |
| ---------------- | ---------------------------------------------------------- | ------------------------------------------------------------- |
| 외부 제약        | 우리 저장소 밖에서 정해진 값이라 코드만 봐서는 근거가 없다 | 서드파티 API가 초당 5회로 제한한다                            |
| 호출 순서 가정   | 순서를 바꿔도 타입 검사와 lint를 통과한다                  | 이 초기화가 provider 마운트보다 먼저 끝나야 한다              |
| 우회 코드의 근거 | 왜 이상하게 짰는지를 코드가 설명할 방법이 없다             | 라이브러리 버그를 피하려고 이 순서로 둔다. 이슈 번호를 남긴다 |
| 회귀를 막는 이유 | 지워도 당장은 멀쩡해 보인다                                | 이 줄을 빼면 v1.1.8의 테이블 깨짐이 돌아온다                  |

이 넷에 해당하지 않으면 주석 없이 둔다. 이름을 고쳐서 설명이 필요 없게 만드는 편이 거의 항상 낫다.

## 쓰지 않는 주석

- 코드를 한국어로 다시 읽는 주석. `// 글 목록을 가져온다` 위의 `getPosts()`
- 구역 표지. `// 상태`, `// 핸들러`, `// 렌더`. 구역이 필요할 만큼 길면 함수를 나눈다
- 주석 처리한 코드. git이 기억한다
- 타입을 되풀이하는 JSDoc. `@param slug string`은 시그니처에 이미 있다
- 담당자와 조건이 없는 TODO. 언제 지울지 아무도 모르는 주석은 영구히 남는다
- 파일 머리의 배너. 파일 이름과 경로가 이미 말한다

## 지시문 주석은 주석이 아니다

**모양만 주석이고 실제로는 도구에 주는 명령이다. 지우면 동작이 깨진다.**

| 지시문                            | 지우면 벌어지는 일                                                    |
| --------------------------------- | --------------------------------------------------------------------- |
| `// eslint-disable-next-line ...` | 그 줄에서 lint가 실패한다                                             |
| `/** @vitest-environment node */` | 테스트가 jsdom에서 돌아 파일시스템 접근이 깨진다                      |
| `/** @jsxImportSource ... */`     | JSX 변환이 다른 런타임을 쓴다                                         |
| `// @ts-expect-error`             | 타입 오류가 드러난다. 반대로 오류가 사라지면 이 줄 자체가 실패를 낸다 |
| `// @ts-nocheck`                  | 파일 전체가 타입 검사를 받는다                                        |
| `// prettier-ignore`              | 손으로 맞춘 정렬이 포맷터에 뭉개진다                                  |
| `/* v8 ignore next */`            | 커버리지 집계가 달라진다                                              |

목록은 닫혀 있지 않다. 도구를 새로 붙이면 그 도구의 지시문을 여기에 더한다.

### 실제로 깨뜨린 적이 있다

2026-08-22 저장소 전체에서 설명 주석 695줄을 지웠다. 그때 `/** @vitest-environment node */` 넷을 함께 지워 테스트 23개가 깨졌다. 파일 첫 줄의 블록 주석이라 설명 주석과 생김새가 같았고, 지운 뒤에야 테스트 실행에서 드러났다.

### 일괄 삭제 전에 하는 일

주석을 도구나 스크립트로 한꺼번에 지우려면 **먼저 지시문을 전수 조사하고 삭제 대상에서 뺀다.**

```bash
grep -rnE "eslint-disable|@vitest-environment|@jsxImportSource|@ts-nocheck|@ts-expect-error|@ts-ignore|prettier-ignore|v8 ignore|c8 ignore" \
  --include="*.ts" --include="*.tsx" --include="*.mjs" --include="*.js" \
  --exclude-dir=node_modules --exclude-dir=.next --exclude-dir=.git .
```

걸린 줄을 목록으로 만든 다음 삭제를 돌린다. 삭제가 끝나면 `pnpm type:check`와 `pnpm test`, `pnpm lint`를 전부 돌려 대조한다. 지시문을 지운 사고는 타입 검사만으로는 드러나지 않는다.

## 쓸 때 지킬 것

- 무엇을 하는지는 코드에 있다. 왜 그렇게 했는지를 적는다
- 한국어로 쓴다. 코드 식별자는 영어 그대로 둔다
- 설명할 코드 바로 위에 붙인다. 멀어지면 따로 논다
- 근거가 저장소 밖에 있으면 링크나 이슈 번호를 남긴다. 링크 없는 "라이브러리 버그 때문"은 확인할 방법이 없다
- 주석이 길어지면 주석을 다듬기 전에 코드를 고칠 자리인지 먼저 본다
- 코드를 고치면 위의 주석도 함께 고친다. 틀린 주석은 없는 주석보다 나쁘다
