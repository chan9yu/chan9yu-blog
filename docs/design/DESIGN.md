# chan9yu 개발 블로그 디자인 방향

블로그가 주는 인상과 그것을 만드는 규칙을 적는다. 화면별 상세는 DESIGN-SPEC.md에 적는다.

현재 구현을 서술한다. 값은 전부 코드에서 실측한 것이고, 코드와 어긋나는 서술을 발견하면 코드를 실측해 이 문서를 고친다.

## 인상

차분하다. 정확하다. 읽기 편하다.

긴 기술 글을 끝까지 읽게 만드는 것이 목적이라 화면이 먼저 눈에 띄면 안 된다. 장식은 콘텐츠가 요구할 때만 넣고, 색은 의미가 있을 때만 쓴다. 개성은 요소를 더해서가 아니라 본문 조판의 정확도와 상호작용의 매끄러움에서 나온다.

이 셋이 아래 모든 선택의 기준이다. 어떤 요소를 넣을지 망설여지면 그것이 읽기를 돕는지 묻고, 아니면 뺀다.

## 지원 범위

모든 화면을 지원한다. 어느 기기에서든 기능이 빠지지 않고 배치만 달라진다.

### 폭 구간

Tailwind 4 기본 브레이크포인트를 그대로 쓴다. 구간마다 대표 기기와 결정할 것을 적었다.

| 구간 | 폭          | 대표 기기                   | 이 구간에서 정하는 것              |
| ---- | ----------- | --------------------------- | ---------------------------------- |
| base | 320~639px   | 모바일 세로                 | 1단 배치, 본문 폭이 곧 화면 폭     |
| sm   | 640~767px   | 큰 모바일 세로, 모바일 가로 | 여백 확대, 카드 내부 2단 허용      |
| md   | 768~1023px  | 태블릿 세로                 | 헤더 네비 노출, 카드 격자 2열      |
| lg   | 1024~1279px | 태블릿 가로, PC 저해상도    | 사이드바 노출, 본문과 사이드바 2단 |
| xl   | 1280~1535px | 일반 PC                     | 본문 44rem 상한이 여백으로 드러남  |
| 2xl  | 1536px 이상 | 고해상도 PC, 4K             | 콘텐츠 폭 고정, 좌우 여백만 증가   |

`--container-content`는 72rem, `--container-prose`는 44rem이다. 2xl 이상에서도 이 상한을 넘기지 않는다. 화면이 넓어지면 콘텐츠가 커지는 것이 아니라 좌우 여백이 늘어난다. 4K에서 본문이 화면을 가로지르면 줄 길이가 무너져 읽을 수 없게 된다.

### 높이 구간

모바일 가로는 폭이 아니라 높이가 문제다. 폭은 700px을 넘는데 높이가 400px 아래라, 폭 기준 브레이크포인트만으로는 잡히지 않는다. 높이 기준 쿼리를 따로 둔다.

```css
@media (max-height: 480px) { ... }
```

이 구간에서 적용할 규칙은 다음과 같다.

- 헤더의 `sticky`를 해제한다. 높이 400px 화면에서 상단 76px을 고정으로 뺏기면 본문이 남지 않는다
- 바텀시트의 최대 높이를 평소 72vh에서 `calc(100vh - 3rem)`로 바꾼다. 72vh는 세로 화면 기준이라 가로에서는 실제 높이가 너무 얕다. 모달 내용(60vh)과 라이트박스(90vh)는 화면 높이에 비례하므로 그대로 둔다
- 화면 하단 고정 요소의 위치를 올려 본문 가림을 줄인다. 맨 위로 버튼은 아래 여백이 2rem에서 3rem이 되고 목차 열기 버튼은 1.5rem에서 2.5rem이 된다

### 픽셀 밀도

논리 해상도와 별개로 물리 픽셀 밀도(DPR) 1배와 2배, 3배를 모두 지원한다.

- 이미지는 `next/image`가 `sizes` 속성 기준으로 밀도별 후보를 만든다. `sizes` 생략을 금지한다
- 테두리는 물리 픽셀 1px이 아니라 CSS 1px로 둔다. 고밀도 화면에서 얇아 보이는 것은 의도한 결과다
- 아이콘은 전부 SVG라 밀도 대응이 필요 없다. 래스터 아이콘을 새로 넣지 않는다

### 입력 방식

포인터 종류를 가정하지 않는다. 태블릿 가로처럼 큰 화면에 손가락 입력이 오는 조합이 실재한다.

- 터치 대상은 최소 44x44px을 유지한다. WCAG 2.2의 2.5.8 Target Size 최소 기준은 24x24px이지만 그보다 넉넉하게 잡는다
- hover에만 있는 정보를 만들지 않는다. hover는 이미 보이는 것을 강조하는 데만 쓴다
- hover 효과는 `@media (hover: hover)` 안에 둔다. 터치 기기에서 탭 후 hover 상태가 남는 것을 막는다

### 대비 기준

WCAG 2.2의 AA를 기준으로 삼는다. WCAG 3.0은 2030년 이후 완료 전망이고 APCA는 확정 표준이 아니므로 검증 기준으로 쓰지 않는다.

- 본문 텍스트는 배경 대비 4.5대 1 이상
- 큰 제목(24px 이상 또는 18.66px 이상 굵은 글자)은 3대 1 이상
- 테두리와 아이콘 같은 비텍스트 요소는 3대 1 이상
- 코드 하이라이트는 7대 1을 목표로 한다

옅은 색과 가는 글자로 만드는 저대비 미니멀리즘은 쓰지 않는다. 인상이 차분한 것과 글자가 안 보이는 것은 다르다.

## 타이포그래피

본문 폰트는 Pretendard Variable 하나이고 `next/font/local`로 자체 호스팅한다. 코드 폰트는 시스템 모노스페이스를 쓴다.

### 본문 조판

| 항목      | 값                             | 근거                                                        |
| --------- | ------------------------------ | ----------------------------------------------------------- |
| 본문 크기 | 모바일 1rem, md 이상 1.0625rem | 최소 16px 권고. 한글은 같은 크기의 라틴보다 작아 보인다     |
| 줄 간격   | 1.85                           | 한글 본문 권고 범위는 글자 크기의 150에서 190퍼센트다       |
| 본문 폭   | 44rem                          | 한글 약 44자에 해당하고 WCAG 1.4.8의 CJK 40자 권고에 가깝다 |
| 문단 간격 | 1.625em                        | 들여쓰기 대신 여백으로 문단을 나눈다                        |
| 정렬      | 왼끝 맞춤                      | 양끝 맞춤은 어절 사이가 벌어져 한글에서 얼룩이 생긴다       |

본문 폭은 `prose.css`의 `.prose`에 `max-width: var(--container-prose)`로 걸려 있다. 목차를 옆에 두는 화면에서도 본문이 남는 폭을 다 쓰는 대신 44rem에서 멈추고 남는 공간은 여백이 된다.

### 타입 스케일

체계는 하나다. `globals.css`의 `@theme`이 Tailwind 기본 스케일을 시안 값으로 재정의하므로 화면은 `text-*` 유틸을 그대로 쓰면 이 값이 적용된다.

| 단계        | 크기         | 확인된 사용처                   |
| ----------- | ------------ | ------------------------------- |
| `text-4xl`  | `2.125rem`   | 홈 인사말(폭 420px 이상)        |
| `text-3xl`  | `1.8125rem`  | 홈 인사말 기본                  |
| `text-2xl`  | `1.5625rem`  | 페이지 제목                     |
| `text-xl`   | `1.1875rem`  | 로고(md 이상)                   |
| `text-lg`   | `1.0625rem`  | 로고 기본, 인사말 설명(md 이상) |
| `text-base` | `0.96875rem` | UI 본문                         |
| `text-sm`   | `0.84375rem` | 카드 설명, 버튼, 네비           |
| `text-xs`   | `0.78125rem` | 날짜, 메타 정보                 |

전용 단계가 둘 더 있다. 태그 칩의 `text-chip`(0.71875rem, 줄 간격 1.5)과 부제의 `text-subtitle`(0.90625rem, 줄 간격 1.6)이다.

줄 간격 토큰은 `leading-tight` 1.45, `leading-snug` 1.55, `leading-prose` 1.85 셋이다. 자간 토큰은 `tracking-hero` -0.035em, `tracking-title` -0.03em, `tracking-heading` -0.02em, `tracking-flat` -0.015em 넷이다.

글 본문의 제목 크기는 `prose.css`가 따로 정한다. h2가 1.5625rem 굵기 700, h3가 1.1875rem 굵기 700, h4가 1.0625rem 굵기 600이고 줄 간격은 셋 다 1.45다.

제목은 앞 문단보다 뒤따르는 문단에 가깝게 둔다. 위 여백을 아래 여백의 1.5배 이상으로 잡는다.

### 한글 줄바꿈

현재 본문 문단과 제목에 `word-break: keep-all`을 걸어 어절 단위로 줄을 바꾼다.

이 선택에는 조사와 어긋나는 지점이 있다. W3C의 한국어 스크립트 노트는 현대 한국어에서 음절 경계 줄바꿈이 더 흔하다고 적고, `keep-all`은 좁은 컨테이너에서 넘침을 만든다. 반면 이 블로그는 v1.1.8에서 모바일 표가 음절 단위로 한 글자씩 깨지는 문제를 겪었고 그때 `keep-all`이 해결책이었다.

그래서 다음 조건에서 `keep-all`을 유지한다.

- 제목과 본문 문단에 적용한다. 짧은 텍스트에서 어절이 끊기면 의미 단위가 무너진다
- 항상 `overflow-wrap: break-word`를 함께 건다. URL이나 긴 영문 식별자가 넘치는 것을 막는다
- 표 안에서는 `overflow-wrap: anywhere`로 예외를 둔다. 셀 폭이 좁아 어절 하나가 셀보다 길어질 수 있다
- 본문 폭이 좁아지는 base 구간에서 넘침이 생기면 `keep-all`을 완화한다

### 한글과 영문 혼용

기술 글에는 영문 식별자와 인라인 코드가 본문에 섞인다. 같은 크기로 두면 라틴 글자가 작아 보인다. 인라인 코드는 본문의 0.9em이라 더 작아지므로, 크기 대신 배경색으로 구분을 만든다.

## 간격과 모서리

기본 간격 단위는 0.25rem이다. 화면마다 다른 값이 나오기 시작하면 이 절로 돌아와 단계를 늘린다.

| 항목      | 값                                                                               |
| --------- | -------------------------------------------------------------------------------- |
| 모서리    | `xs` 0.25rem, `sm` 0.375rem, `md` 0.5rem, `lg` 0.75rem, `xl` 1rem, `full` 9999px |
| 좌우 여백 | base `1rem`, sm `1.5rem`, lg `2rem`                                              |
| 세로 여백 | 페이지 `2rem`에서 lg `2.5rem`                                                    |
| 구역 간격 | base `2.5rem`, sm `3.5rem`                                                       |
| 카드 패딩 | base `1rem`, sm `1.25rem`, lg `1.75rem`                                          |

카드와 버튼은 `lg`(0.75rem), 본문 코드 블록은 10px, 태그 칩은 `sm`(0.375rem)을 쓴다.

그림자는 세 단계다. 라이트에서는 옅게(0.06에서 0.12 불투명도), 다크에서는 진하게(0.4에서 0.6) 둔다. 다크에서 옅은 그림자는 보이지 않기 때문이다.

## 디자인 시스템

### 외부 UI 라이브러리를 쓰지 않는다

컴포넌트를 직접 만든다. shadcn/ui와 그 기반인 Radix를 쓰지 않는다. 디자인 시스템을 프로젝트가 소유하는 것이 목적이다. 남의 컴포넌트에 우리 토큰을 덮어씌우는 대신, 우리 토큰 위에 우리 컴포넌트를 올린다.

의존성에 `radix-ui`와 `class-variance-authority`, `sonner`, `tw-animate-css`, `shadcn`이 없다. variant는 CVA 대신 값 매핑 객체와 `cn()` 조합으로 처리한다.

### 계층

세 층으로 쌓는다. 아래층이 위층을 알지 못한다.

| 층         | 내용                                                    | 위치                                             |
| ---------- | ------------------------------------------------------- | ------------------------------------------------ |
| 토큰       | 색, 타이포, 간격, 모서리, 그림자, 모션 값               | `src/app/styles/tokens.css`                      |
| 프리미티브 | 도메인을 모르는 UI 조각. 버튼, 태그 칩, 대화상자        | `src/shared/ui/`                                 |
| 패턴       | 블로그의 개념을 아는 조합. 포스트 카드, 목차, 검색 모달 | `src/entities/`, `src/features/`, `src/widgets/` |

프리미티브는 포스트나 태그를 알지 못한다. 그 지식은 패턴 층에만 있다. 이 경계가 무너지면 컴포넌트를 다른 화면에 못 쓰게 된다.

| Button                                            | variant 3종(outline, accent, ghost)에 높이 2.75rem 단일. href를 주면 Link로 렌더된다               |
| Dialog                                            | 네이티브 dialog 요소의 showModal 위에 Tab 순환과 열었던 요소로의 포커스 복원, 스크롤 잠금을 얹는다 |
| Drawer                                            | Dialog에 방향(bottom, right)과 슬라이드만 얹는다                                                   |
| TagChip                                           | sm, md, lg 세 크기와 active 상태. href가 없으면 span으로 렌더된다                                  |
| Container                                         | 페이지 공통 폭과 좌우 여백                                                                         |
| NavLink                                           | 현재 경로를 강조하는 네비 링크                                                                     |
| Breadcrumb, SectionTitle, EmptyState, SocialLinks | 경로 안내와 구역 제목, 빈 상태 안내, 소셜 링크                                                     |
| ScrollToTop, ScrollReset                          | 맨 위로 버튼과 라우트 이동 시 스크롤 초기화                                                        |

별도의 Toast와 Skeleton, VisuallyHidden, FocusTrap 프리미티브는 없다. 복사 알림은 공유 버튼 컴포넌트가 `role="status"` 라이브 리전으로 직접 그리고, 화면 낭독 전용 텍스트는 `sr-only` 유틸 클래스로 처리하며, 포커스 가두기는 Dialog 안에 들어 있다. Badge와 Accordion, DropdownMenu는 쓰는 곳이 없어 만들지 않았고 Tooltip은 필요해질 때 만든다.

프리미티브는 FSD의 shared 레이어 `ui` 세그먼트에 둔다. 배럴 없이 `shared/ui/Button`처럼 직접 경로로 가져온다.

### 직접 만들 때 빠뜨리기 쉬운 것

라이브러리가 대신 해주던 것의 목록이다. 대화상자 계열을 직접 만들 때 접근성이 무너지는 자리가 여기다.

- 열리면 포커스를 안으로 옮기고 Tab이 밖으로 나가지 않게 가둔다
- 닫으면 열기 전 눌렀던 버튼으로 포커스를 되돌린다
- 대화상자 역할과 모달 의미를 보조 기술에 전달한다. 네이티브 dialog의 showModal이 이것을 맡고, 제목은 `aria-labelledby`로 연결한다
- ESC로 닫는다. 여러 겹이 열려 있으면 맨 위 하나만 닫힌다
- 열려 있는 동안 뒤 배경이 스크롤되지 않게 한다. 잠글 때 스크롤바 폭만큼 여백을 보정해 화면이 튀지 않게 한다
- 바깥 클릭으로 닫되 눌러서 안에서 시작한 드래그가 밖에서 끝난 경우는 닫지 않는다
- 뒤 배경의 요소를 보조 기술에서 감춘다

이 목록을 만족하는지는 컴포넌트마다 테스트로 증명한다. 눈으로 확인하는 것으로는 부족하다.

### 스타일 규칙

- 임의값을 쓰지 않는다. 토큰이 만든 유틸(`max-w-content`, `border-border-subtle`)이나 표준 클래스를 쓰고, 필요한 값이 없으면 토큰을 늘린다
- 프리미티브는 바깥 여백을 스스로 갖지 않는다. 배치는 쓰는 쪽이 정한다
- 프리미티브는 `className`을 받아 마지막에 병합한다. 쓰는 쪽이 덮어쓸 수 있어야 한다
- 배럴 파일을 만들지 않는다. `shared/ui/Button`처럼 직접 경로로 가져온다

## 모션

### 원칙

애니메이션은 상태 변화를 알리는 데만 쓴다. 무엇이 어디서 어디로 갔는지 보여주는 것이 목적이고, 시선을 끄는 것이 목적이면 넣지 않는다.

스크롤을 가로채는 연출과 큰 면적의 패럴랙스는 쓰지 않는다. 방향 감각을 잃게 하고 모션 민감 사용자에게 위험하다. 스크롤에 반응해 콘텐츠가 드러나는 정도까지만 허용한다.

### 수치

| 상황                    | duration | easing                       |
| ----------------------- | -------- | ---------------------------- |
| 즉각 피드백(토글, 복사) | 100ms    | `ease-out`                   |
| 색과 테두리 전환        | 150ms    | `ease-out`                   |
| 요소 등장               | 250ms    | `cubic-bezier(0, 0, 0, 1)`   |
| 요소 퇴장               | 200ms    | `cubic-bezier(0.3, 0, 1, 1)` |
| 화면 전환, 모달         | 300ms    | `cubic-bezier(0.2, 0, 0, 1)` |
| 이미지 확대             | 500ms    | `ease-out`                   |

500ms를 넘기면 사용자가 지체로 느낀다. 퇴장은 등장보다 짧게 잡는다. 사라지는 요소는 다음 동작보다 주의를 덜 요구하기 때문이다. 전환이 덮는 면적이 클수록 길게 잡아 속도감을 맞춘다.

### 모션 축소 대응

세 겹으로 막고 예외를 하나 둔다.

- 전역 CSS에서 `prefers-reduced-motion: reduce`일 때 애니메이션과 전환 시간을 0.01ms로 줄인다
- View Transitions는 전역 선택자에 잡히지 않으므로 별도로 `animation: none` 처리를 한다
- 위치 이동을 동반하는 효과는 `motion-safe:` 접두를 붙인다

예외는 불투명도다. 불투명도만 바뀌는 페이드는 모션 민감 사용자에게도 안전하므로, `data-motion="fade"`가 붙은 요소는 축소 모드에서도 불투명도 전환을 유지한다.

### 스크롤과 페이지 전환

- 목록 카드의 등장은 CSS 스크롤 타임라인(`animation-timeline: view()`)으로 동작한다. 스크롤 리스너가 없고 미지원 브라우저는 애니메이션 없이 정상 표시된다
- 페이지 이동은 `@view-transition` 규칙으로 문서 간 전환을 켜 크로스페이드한다

## 다크 모드

지원한다. 기본값은 시스템 설정을 따르고 헤더의 토글로 바꾼다. 선택은 브라우저에 저장된다.

- `next-themes`의 클래스 방식을 쓴다. `html` 요소의 `.dark` 클래스가 토큰 그룹을 덮어쓴다
- `color-scheme`은 인라인 스타일이 아니라 CSS에서 `.dark` 선택자로 직접 선언한다
- 전환은 View Transitions API로 300ms 크로스페이드다. 미지원 브라우저는 애니메이션 없이 즉시 바뀐다
- hydration 이전에는 토글 아이콘을 투명 자리표시자로 렌더해 깜빡임과 레이아웃 이동을 막는다

전환 경로는 하나다. `next-themes`의 전환 차단 옵션(`disableTransitionOnChange`)을 켜 개별 요소의 색 전환을 막고, 테마 전환은 `document.startViewTransition` 한 갈래로만 간다.
